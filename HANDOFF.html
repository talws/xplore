Xplore — handoff

Xplore is a standalone local tool that captures your x.com bookmarks, resolves

and archives the articles they link to, classifies everything by topic, and makes

the lot searchable. It currently lives at C:\Users\mihal\Desktop\Code\xcollector

and runs on port 8502 (the port the earlier, lost tool used).

It is deliberately separate from Mneme. That is an owner decision, recorded

2026-09-04 and not to be revisited casually: browser bookmarks and x.com

bookmarks are different collections and keep different stores. Searching the two

together is a federation job, not a merge. Do not add an x collection to

Mneme, and do not route tweets or their articles through Mneme's store.

    Architecture

    Capture is interception, not scraping. The extension hooks the page's

    XMLHttpRequest and matches the GraphQL operation name — Bookmarks for the

    timeline, TweetDetail for threads. Three things were established the hard way

    and must not be undone:

  • A normal content script runs in an isolated world and its window is not the page's, so patching XHR there catches nothing. The interceptor must be a "world": "MAIN" content script.
  • Inline <script> injection does not execute on x.com (CSP). MAIN-world manifest registration is the only route; Firefox MV2 would use wrappedJSObject, userscripts use unsafeWindow.
  • X uses XHR, not fetch. Patching fetch catches nothing.
  • Content-script fetch to localhost is refused in MV3 — a simple GET slips through, but any preflighted POST from an https page to a loopback address is blocked before the server sees it. All network calls go through the service worker, which runs under the extension's own host permissions.

    • Parsing happens server-side, in Python, from the raw response. When X

    renames a field the fix is a server edit and a re-parse, not an extension

    release. Unparsable payloads are saved to unparsed/ so they can be replayed

    offline.

    Scheduling is chrome.alarms in the service worker, not a page timer. A

    page setTimeout only fires while that exact tab is open and unfrozen — that

    mistake silently skipped 7 September. The alarm wakes hourly, acts when a sync

    is ~20h overdue, opens a background tab if none exists, and closes it after.

    A watchdog abandons any run that has not reported back in 30 minutes.

    /i/bookmarks now 302s to /i/history, but the GraphQL operation was not

    renamed with the route. Match the operation, not the path; both paths are handled.

    Traps that have already cost time

    Found on the night of 12–13 September:

  • Lock contention drops bookmarks silently. transcripts.py committed every 5 videos at ~30s each, holding a write transaction for ~2½ minutes, while the server had SQLite's 5s default timeout. Result: 32 × database is locked and 500s on /api/ingest — bookmarks not captured. Fixed with commit-per-row and PRAGMA busy_timeout = 30000 in store.py. **Any new pass must commit per row and set a busy timeout. Never run two sessions writing this DB at once.**
  • ask(kind, body) silently dropped extra fields. The thread post never sent root, so the server got root=undefined, never marked the tweet fetched, and the pass reloaded one permalink forever. Fixed; the queue now also counts attempts at hand-out (max 2), plus a 45s stall timeout and a same-URL guard, so no single tweet can stall the pass again.
  • Ordering by reply_count picks viral tweets, not threads. The first offer was a 13,940-reply post whose page froze the renderer. Now: self-declared threads first (🧵, "1/", "a thread"), and reply_count < 5000 excluded.
  • Mneme's server has the same command line. Both run as python server.py with relative paths, so killing by command line would take down Mneme on
  • Find the owner of 8502 with netstat -ano and kill only that PID and its parent.
  • A failed call looked like an empty queue. "no threads queued" fired on errors too. The panel now says server error N or server unreachable.
  • Buffered logs hide deaths. The transcript pass died after 5 videos with an empty log. Run passes with python -u and write an exit marker.

    • Earlier:

  • cp1253 kills the server on startup. The banner prints box-drawing characters; launched from the login script, stdout is a redirected file in the legacy Greek codepage, and the UnicodeEncodeError kills the process *before it binds the port*. It looked exactly like "no new bookmarks" for two days. sys.stdout.reconfigure(encoding="utf-8", errors="replace") is at the top of server.py — keep it in anything new that prints.
  • Get-NetTCPConnection is unreliable on this machine. It reports nothing while the port is plainly serving. Use netstat -ano. Trusting it once caused me to kill the running server.
  • **PowerShell *> writes UTF-16 logs.** A grep for a completion line in such a log never matches, which left a background waiter spinning forever. Use | Out-File -Encoding utf8.
  • archive.org has rate-limited this machine before. Wayback pacing (8s, a longer pause every fifth, exponential backoff on 403) is not tunable downward. The dead links exist only there.
  • Removal must be a tombstone. The tweet is still bookmarked on x.com, so a hard delete is silently undone by the next sync. tweets.deleted + skip in upsert_tweets.
  • A shorter capture must never overwrite a longer one, or re-running the collector destroys text an expansion pass recovered.
  • t.co returns HTTP 200, not a 3xx. The destination is in a meta-refresh and a JS location.replace. A redirect-only resolver marks every t.co link "resolved to itself" — which the first pass did.

    • Known limitations, stated plainly

  • Bookmark dates for the 27,000 backfilled tweets are all 2026-09-05. X does not say when a bookmark was made. Recent filters (24h/3d/7d/month) become accurate as that date recedes, but the historical distribution never will — you cannot ask "what did I bookmark in March 2024". Possible fix: timeline entries carry a snowflake-shaped sortIndex; one decoded to 2023-04-23, plausible for the oldest bookmark. Columns tweets.sort_index / bookmarked_at exist and are empty. Needs the interceptor to record sortIndex plus one full re-scrape (~18h, idempotent). Validity test: a bookmark cannot predate its tweet. Unverified hypothesis.
  • Thread detection under-counts. is_thread fires on tweets that are replies, but the commonest bookmark is a thread's opener, which is indistinguishable from a standalone tweet in the payload. The queue unions that flag with text markers (🧵, "1/", "a thread"). It is a heuristic.
  • The parser was written against a synthetic payload — the real Bookmarks shape was never directly observed, because Chrome's devtools bridge does not surface these XHRs (x.com runs a service worker). It handled 27,000 real tweets with one quarantined payload, which turned out to be the end-of-timeline marker. test_parse.py is a regression net, not proof.
  • Hard paywalls are genuinely lost to automation. Only 25% of http401 were recovered; the Wayback crawler hits the same wall. TODO-1 is the answer.
  • "Caught up" is a heuristic — 3 barren pages, ~75 tweets past the last new one. Verified once with the Deep button (walks ~1,000 deep): found 0 new, so the shortcut is sound. Worth re-running monthly as a drift check.
